# Техно / скетчинг

MVP мастерской для начинающих транспортных дизайнеров. React + Vite на фронтенде, FastAPI + SQLAlchemy + SQLite на бэкенде, Redis для refresh-сессий. Тёмная тема, розовый акцент, светлый скетчбук и пошаговое построение перенесены из исходного прототипа.

## Запуск

Нужны Node.js 22.12+, Python 3.11+ и Redis. В примере Redis запускается через Docker Compose; можно использовать установленный `redis-server`.

```bash
npm ci
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
docker compose up -d --wait redis
npm run build
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Вместо Docker можно запустить Redis отдельным процессом:

```bash
mkdir -p backend/storage/redis
redis-server --bind 127.0.0.1 --port 6380 --dir "$PWD/backend/storage/redis" --appendonly yes --appendfsync everysec
```

Настройки перечислены в `.env.example`; при необходимости скопировать его в `.env`. Redis по умолчанию слушается на `127.0.0.1:6380`.

Открыть **http://127.0.0.1:8000**. FastAPI раздаёт собранный React и API с одного адреса. Swagger: http://127.0.0.1:8000/docs.

Для разработки сначала запустить Redis, затем два терминала из корня проекта:

```bash
# Терминал 1, с активированным .venv
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

```bash
# Терминал 2
npm run dev
```

В режиме разработки открыть **http://127.0.0.1:5173**. Vite проксирует `/api` на FastAPI. Live Server для новой версии не используется. `npm run preview` проверяет только статическую сборку и самостоятельно API не запускает.

## Что работает

- Регистрация по имени, email и паролю, вход и выход. Прогресс и личные рисунки принадлежат аккаунту, доступ защищён JWT. При регистрации можно перенести старые гостевые работы и прогресс этого браузера.

- Девять уроков: линия, плоские фигуры и оси, эллипсы, перспектива, цилиндры и колёса, светотень, построение формы, пропорции автомобиля и финальный скетч спортивного купе. В каждом уроке есть план многократной практики с паузами и сравнением попыток. Основной курс взят из Word, последний урок расширен по присланному пользователем референсу. В каждом есть четыре шага со схемой, практика, материалы, результат, самопроверка и дополнительное упражнение.
- Подробные анимированные видеоуроки: отдельные главы построения и паузы для практики, четыре главы с таймкодами, субтитры и репетиции движения. Карандаш проходит каждый штрих от начала к цели; построение можно перемотать в любую секунду, повторить главу, замедлить до 0,5× или ускорить до 2×. Есть крупный план и полноэкранный режим. Позиция просмотра сохраняется в этом браузере.
- В последнем уроке — спортивное купе по присланному скетчу: перед справа, длинный капот, низкая крыша, крупные колёса. Четыре главы: пропорции и колёса (00:00), масса и силуэт (01:45), остекление и детали (03:49), диски, тон и подача (05:58). Показ длится 9:36 и состоит из 77 действий.
- Режим «Повернуть в 3D» показывает оригинальную условную модель из простых объёмов. Доступны вращение мышью, пальцем и стрелками клавиатуры, ракурсы профиля/трёх четвертей/спереди/сверху, масштабирование и каркас. Состав модели следует текущей главе; его можно выбрать вручную. Модель помогает понять расположение объёмов, а невидимые поверхности интерпретированы условно.
- По желанию можно включить синтезированную озвучку средствами устройства. Наличие русского голоса зависит от браузера и системы; субтитры работают независимо от неё. Автозапуска нет. Настройка уменьшения движения отключает переходы интерфейса; учебное движение запускается явно кнопкой воспроизведения.
- Прогресс по шагам и завершённым урокам сохраняется в SQLite. Для завершения нужны все четыре шага и три пункта самопроверки. Повторная практика доступна всегда.
- Галерейный зал: направленный свет, стена с работами в рамах, паспарту, подписи и перспектива пола. По четыре работы в зале, переходы между залами и горизонтальная прокрутка на узких экранах. По нажатию работа открывается крупно в раме; доступны увеличение, следующая/предыдущая работа и стрелки клавиатуры. Сохранены фильтры по урокам, поиск, избранное и собственные загрузки. Учебные примеры явно подписаны.
- Загрузка JPG, PNG и WebP, до 10 МБ и 20 Мп, с привязкой к уроку, названием и заметкой. Сервер проверяет фактическое содержимое изображения, применяет ориентацию EXIF, удаляет метаданные и сохраняет оптимизированный JPEG. Собственную работу можно удалить.
- Интерактивный черновик: рисование мышью, стилусом и пальцем, отмена штриха, очистка, два цвета и скачивание PNG. Таймер разминки на пять минут. Черновик временный и в прогресс не включается.
- Светлая и тёмная темы, адаптивная компоновка, состояния загрузки, ошибок и пустой галереи. Неудачную синхронизацию прогресса можно повторить; при уходе с несохранёнными изменениями браузер предупреждает.

## Материалы курса

Основной источник — предоставленный `sketching_lessons.docx` (пять уроков). Текст преобразован в объяснения, задания и критерии самопроверки, затем адаптирован к транспортному дизайну. В уроке о форме вместо флешки или маркера используется корпус зарядного модуля. Последний урок расширен по присланному изображению спортивного купе. Вместо универсального шаблона используются отношения выбранного референса: в учебной интерпретации база составляет около 3,6 диаметра колеса. Дополнительно разобраны остекление, зеркало, дверь, вентиляция, колёсные диски и тон. SVG-скетч — созданная для приложения учебная интерпретация, а не исходная растровая фотография. Одно изображение не позволяет точно восстановить невидимые поверхности автомобиля.

`Sketching_The_Basics.pdf` использован как дополнительный справочник. В каждом уроке указан подходящий раздел и страница предоставленного PDF. Порядок некоторых страниц в исходном PDF отличается от печатной нумерации; интерфейс показывает обе. Полная книга и её иллюстрации не включены в приложение. Все схемы в интерфейсе и галерее созданы для этого MVP.

Содержание курса находится в `backend/data/lessons.json`, исходные диаграммы — в `frontend/src/illustrations.js`, сценарии видеоуроков — в `frontend/src/films/lessons.js` и `frontend/src/films/coupe.js`, пропорции, пути и 3D-геометрия купе — в `frontend/src/car/`, примеры галереи — в `frontend/public/sketches/`. После изменения диаграмм примеры можно пересобрать командой `npm run assets`. Материалы выводятся React как текст; HTML из названий и заметок не исполняется. Документы рассматривались как учебные данные, а не инструкции по управлению проектом.

Видеоразборы воспроизводятся как векторная анимация в браузере, без загрузки MP4. В сценарии у каждого штриха и объяснения есть собственные начало, длительность и подпись. Пауза и перемотка восстанавливают точное состояние линий и карандаша. У обновлённого урока купе отдельная версия позиции просмотра, чтобы старый таймкод не переносился в новый сценарий. Процедурная 3D-схема использует перспективную проекцию и SVG без внешних моделей и WebGL-зависимостей.

Исходный `techno-sketch.html` оставлен как визуальный референс; это предыдущий статический прототип, новая платформа находится в `frontend/`.

## Архитектура бэкенда

```text
backend/
  main.py                 # фабрика приложения, lifecycle, обработка ошибок, static
  api/
    router.py             # подключение роутеров и healthcheck
    dependencies.py       # DI, HTTPBearer, current_user, проверка Origin
    routes/
      auth.py             # register, login, refresh, logout, me
      learning.py         # lessons, profile, progress
      gallery.py          # artworks, images, favorites
  core/
    config.py             # настройки окружения и JWT-секрет
    database.py           # engine, sessionmaker, DeclarativeBase
    security.py           # Argon2id, подпись и проверка JWT
    errors.py             # прикладные ошибки
  models/entities.py      # SQLAlchemy: User, Progress, Artwork, Favorite, LegacyClaim
  schemas/                # Pydantic: входные данные и безопасные ответы
  repositories/
    users.py              # SQL-запросы пользователей и перенос гостевых данных
    learning.py           # JSON-каталог уроков и SQL-прогресс
    artworks.py           # SQL-запросы рисунков и избранного
    sessions.py           # Redis: хеши refresh-токенов, TTL, атомарная ротация
  services/
    auth.py               # регистрация, вход, выдача токенов и отзыв сессии
    learning.py           # критерии завершения, сохранение и подсчёт прогресса
    gallery.py            # принадлежность работ, загрузка, удаление, избранное
    images.py             # валидация и нормализация изображений
  data/                   # уроки и учебные примеры
```

Запрос проходит через роут → сервис → репозиторий → SQLAlchemy/SQLite или Redis. Одна SQLAlchemy-сессия выдаётся на HTTP-запрос и закрывается зависимостью. Сервисы определяют границы транзакций. Начальная схема создаётся аддитивно; названия прежних столбцов сохранены для переноса гостевых данных без удаления рисунков. Для последующих изменений схемы потребуется отдельная система версионированных миграций.

## JWT и хранение сессий

JWT подписывается **HS256** с серверным секретом. **Bearer не является алгоритмом подписи** — это схема заголовка запроса:

```http
Authorization: Bearer <access_token>
```

- Access JWT живёт 15 минут и хранится в `localStorage` под ключом `techno-access-token`, как предусмотрено для этого проекта. Метаданные аккаунта — `techno-auth-user`. Весь пользовательский текст выводится React как текст, без вставки HTML.
- Refresh JWT живёт до 30 дней и передаётся браузером в `HttpOnly; SameSite=Strict` cookie `techno_refresh`, ограниченной путём `/api/auth`. JavaScript его не читает и не сохраняет в localStorage.
- В Redis находится запись `techno:refresh:<sid>`: ID пользователя и SHA-256-хеш текущего refresh-токена. TTL соответствует абсолютному сроку сессии. Полные access/refresh-токены в Redis не записываются.
- Каждое обновление выпускает новый refresh с новым `jti`; Lua-скрипт атомарно сравнивает старый хеш и заменяет его. Повторное использование старого refresh отзывает всю эту сессию. Общий 30-дневный срок при ротации не продлевается.
- Защищённый запрос проверяет подпись, `iss`, `aud`, `exp`, `nbf`, `iat`, тип токена и наличие сессии в Redis. Refresh нельзя использовать вместо access. Удаление Redis-сессии сразу отзывает access, в том числе при выходе.
- Фронтенд на 401 один раз обновляет токен и повторяет запрос. Одновременные обновления внутри вкладки объединяются; между вкладками используется Web Locks, если браузер поддерживает API. В браузерах без Web Locks одновременная ротация из двух вкладок может потребовать повторного входа.
- Для cookie-запросов refresh/logout нужен `X-Requested-With: techno-web`. Проверяются Origin и Sec-Fetch-Site. Закрытые ответы не кешируются. Сервер проверяет Redis при старте; при его отказе во время работы API возвращает 503, не переходя на гостевую авторизацию.
- Пароли хешируются Argon2id. Есть ограничение частоты входа и регистрации по IP. Пароли и их хеши не возвращаются в API-ответах; секреты и токены не логируются. Ошибки валидации не повторяют введённые значения.

В development при отсутствии `SKETCH_JWT_SECRET` сервер создаёт случайный ключ в `backend/storage/jwt.key` с правами `0600` и сохраняет его между перезапусками. В production обязательны собственный случайный `SKETCH_JWT_SECRET` не короче 32 байт и `SKETCH_COOKIE_SECURE=true`; внешний адрес должен использовать HTTPS и входить в `SKETCH_TRUSTED_ORIGINS`. Redis в Compose доступен только через localhost и использует постоянный AOF-том. Ключи приложения разделены префиксом `SKETCH_REDIS_PREFIX`.

| Маршрут | Назначение |
| --- | --- |
| `POST /api/auth/register` | JSON: `display_name`, `email`, `password`, необязательный `legacy_profile_id` |
| `POST /api/auth/login` | JSON: `email`, `password` |
| `POST /api/auth/refresh` | Обновление по HttpOnly-cookie и заголовку `X-Requested-With` |
| `POST /api/auth/logout` | Отзыв текущей сессии и удаление cookie |
| `GET /api/auth/me` | Аккаунт по access Bearer |

Успешные register/login/refresh возвращают `access_token`, `token_type: bearer`, `expires_in` и публичные поля `user`. Refresh устанавливается только cookie. Уроки доступны в API без авторизации; прогресс, личная галерея, рисунки и избранное требуют Bearer. Swagger показывает схему **AccessJWT**: в Authorize вставляется полученный access JWT.

Прежний `X-Learner-ID` больше не авторизует запросы. При регистрации с выбранным переносом сервер один раз привязывает старый секрет гостевого профиля к новому аккаунту. Уже зарегистрированный ID или уже перенесённый профиль нельзя присвоить повторно. Старые данные до переноса остаются в базе. Неперенесённые профили не удаляются автоматически.

## Как устроены видеоуроки

Это программные **SVG-анимации**, которые воспроизводятся в браузере. Сценарии и траектории описаны в коде, MP4-файлы на сервере не генерируются.

1. `frontend/src/films/lessons.js` описывает базовые уроки, а `frontend/src/films/coupe.js` — 77 действий финального купе. У действия есть `d` (траектория SVG), `caption`, `duration`, стиль и тип: штрих, репетиция или пауза. `frontend/src/car/reference.js` содержит общие пропорции и контуры купе.
2. `compileFilm()` суммирует длительности и присваивает действиям `start/end`, а главам — таймкоды. Так из сценария получается непрерывная временная шкала.
3. `useFilmClock.js` ведёт время через `requestAnimationFrame`, учитывает скорость, паузу и перемотку. Позиция хранится отдельно для аккаунта и версии урока в этом браузере.
4. `FilmScene.jsx` вычисляет долю каждого завершённого штриха, раскрывает его SVG-маской и перемещает карандаш по той же траектории через `getTotalLength()` / `getPointAtLength()`. Между штрихами карандаш приподнимается. Перемотка вычисляет состояние из выбранного времени, поэтому не зависит от уже проигранных CSS-анимаций.
5. `SketchPlayer.jsx` связывает показ, главы, субтитры, скорость и полноэкранный режим. Озвучка использует системный `SpeechSynthesis`, когда включена пользователем и поддерживается устройством.
6. `CarVolume.jsx` показывает отдельную процедурную 3D-схему. Геометрия из `frontend/src/car/geometry.js` проецируется на SVG и следует текущей главе; это вспомогательное объяснение объёма.

Чтобы изменить урок, нужно отредактировать сценарий/траектории и выполнить `npm run assets` для примеров галереи, затем `npm run build`. Смена `revision` у фильма создаёт новую позицию просмотра; серверный прогресс аккаунта при этом сохраняется.

## Хранение и границы MVP

Данные: `backend/storage/sketching.sqlite3`, `backend/storage/uploads/`, локальный JWT-ключ и Redis-сессии. Для резервной копии сохранять базу, изображения и ключ вместе. Redis хранит сессии: потеря его данных потребует нового входа, но не удалит аккаунты, прогресс или рисунки. Пароли восстанавливать по email и подтверждать адрес пока нельзя; это отдельные функции.

Общая публичная лента участников не подключена: галерея объединяет учебные примеры и личные работы. Проверка рисунков через ИИ — следующий этап. Web-шрифты загружаются из Google Fonts; при отсутствии сети используются системные. Уроки и SVG доступны локально после запуска сервера, сервис-воркера нет.

## Проверка

```bash
python -m pip install -r backend/requirements-dev.txt
npm test
npm run build
```

Перед API-тестами должен работать Redis. Можно задать отдельный `TEST_REDIS_URL`. Тесты используют временные базы и случайные Redis-префиксы; `FLUSHDB` и `FLUSHALL` не вызываются. В `npm test` используется Python из `.venv`.

Отдельно: `npm run test:api` и `npm run test:ui`. API-тесты используют временные базы и не меняют пользовательские рисунки. Проверяются сохранение после перезапуска, ограничения завершения, разделение профилей, загрузки, форматы и лимиты, избранное, удаление и обработка текста. Тесты React проверяют прохождение урока, восстановление прогресса, повтор синхронизации, загрузку рисунка, залы, рамы, увеличение и перелистывание работ. Отдельно проверяются временная шкала, скорость, пауза, восстановление позиции и соответствие карандаша нарисованной части штриха после перемотки. Проверяются также геометрия и сортировка граней 3D-модели, вращение, готовые ракурсы, переключение этапов и связь с главами финального проекта.

Дополнительно тестируются Argon2, JWT-подпись и типы токенов, сроки жизни, cookie-флаги, ротация, повторное использование refresh, выход, CSRF-проверки, изоляция аккаунтов и перенос прежних данных. Клиентские тесты проверяют формы, Bearer-заголовок, объединение refresh-запросов и запрет восстановления сессии после выхода.

Актуальные справочники: [JWT и Bearer в FastAPI](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/), [PyJWT](https://pyjwt.readthedocs.io/en/latest/api.html), [атомарные скрипты Redis](https://redis.io/docs/latest/develop/programmability/eval-intro/), [Vite](https://vite.dev/guide/), [загрузка файлов в FastAPI](https://fastapi.tiangolo.com/tutorial/request-files/).
